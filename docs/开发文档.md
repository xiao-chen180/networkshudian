## 1. 开发环境

| 依赖 | 要求 | 说明 |
| --- | --- | --- |
| JDK | 17+ | 后端 `pom.xml` 指定 `java.version=17` |
| Maven | 3.9+ 或使用 `mvnw` | 根目录提供 Maven Wrapper |
| MySQL | 8.x | 默认库名 `shixun` |
| Node.js | 20.19+ 或 22.12+ | Vite 8 要求；本项目在 Node 22 验证 |
| npm | 9+ | 随 Node 安装 |
| IDE | IntelliJ IDEA / VS Code | 前端建议安装 Vue 官方插件 |

推荐启动方式：

```bash
# 终端 1：后端
cd demo/springboot
../mvnw spring-boot:run      # Windows CMD 使用 ..\mvnw.cmd

# 终端 2：前端
cd demo/vue
npm install
npm run dev
```

访问 `http://localhost:5173`；后端 API 为 `http://localhost:8080`。

## 3. 后端架构

### 3.1 分层结构

```text
HTTP 请求
  └─ Security Filter Chain
       └─ JwtAuthenticationFilter（解析 Bearer Token，写入 SecurityContext）
            └─ Controller（参数校验、取当前用户、返回 ResponseEntity）
                 └─ Service（业务规则、事务）
                      └─ Repository（Spring Data JPA）
                           └─ Entity（表结构映射）
```

### 3.2 包职责

| 包 | 内容 | 职责 |
| --- | --- | --- |
| `config` | `CorsConfig`、`DataInitializer` | 跨域配置；启动时初始化分类与图书 |
| `controller` | 20 个控制器 | 路由、参数解析、鉴权判断、返回 DTO |
| `dto` | 19 个 DTO | 请求 / 响应模型，避免直接暴露实体 |
| `entity` | 20 个实体 | JPA 表映射，含时间戳生命周期回调 |
| `exception` | `CustomException`、`GlobalExceptionHandler` | 业务异常与统一错误响应 |
| `repository` | 19 个仓库接口 | 派生查询、自定义 `@Query` |
| `security` | `SecurityConfig`、`JwtUtil`、`JwtAuthenticationFilter`、`CustomUserDetailsService` | 无状态 JWT 认证 |
| `service` | 16 个服务 | 核心业务逻辑，使用 `@Transactional` 保证写操作一致性 |

### 3.3 启动初始化

[`DataInitializer`](../springboot/src/main/java/com/example/bookstore/config/DataInitializer.java) 实现 `CommandLineRunner`，应用启动后执行：

1. 若 `categories` 表为空，写入 6 个分类；
2. 按 ISBN 逐本 upsert 示例图书（已存在则更新简介、目录、库存）；
3. 为缺少封面的种子图书补全 `image_url = /covers/{isbn}.jpg`，已有封面不会被覆盖；封面文件位于前端 `vue/public/covers/`，由 `scripts/fetch-book-covers.mjs` 抓取；
4. 没有创建任何用户、管理员、优惠券、Banner 或名言数据。

### 3.4 统一响应与异常

成功响应直接返回 DTO / 实体或 `Map`；写操作常用状态码：

| 状态码 | 场景 |
| --- | --- |
| `200 OK` | 查询、更新成功 |
| `201 Created` | 创建成功（注册、下单、创建资源） |
| `204 No Content` | 删除成功 |
| `400 Bad Request` | 业务校验失败（库存不足、重复评论、优惠券不可用等） |
| `401 Unauthorized` | 未携带或无效 Token |
| `403 Forbidden` | 无权限（非本人资源、非管理员） |
| `404 Not Found` | 资源不存在 |
| `500 Internal Server Error` | 未捕获异常 |

错误响应由 [`GlobalExceptionHandler`](../springboot/src/main/java/com/example/bookstore/exception/GlobalExceptionHandler.java) 统一包装：

```json
{ "message": "库存不足", "status": 400 }
```

表单校验失败会额外返回 `errors` 字段；`BadCredentialsException` 统一返回「用户名或密码错误」。

图书列表接口是分页结构：

```json
{
  "content": [ ... ],
  "totalElements": 123,
  "totalPages": 16,
  "number": 0,
  "size": 8
}
```

## 4. 认证与权限

### 4.1 注册与登录

**注册** `POST /api/auth/register`：

1. 校验 `account`、`username`、`email` 唯一性；
2. 密码要求 6–100 位，使用 `BCryptPasswordEncoder` 加密；
3. 若服务端配置了环境变量 `BOOKSTORE_ADMIN_SECRET`（映射到 `bookstore.admin-secret`），且请求携带相同 `adminSecret`，角色为 `ADMIN`、折扣 `1.0`；否则为 `USER`、折扣 `0.95`。未配置时该能力关闭；
4. 保存用户并直接签发 JWT。

**登录** `POST /api/auth/login`：

1. `AuthenticationManager` 调用 [`CustomUserDetailsService`](../springboot/src/main/java/com/example/bookstore/security/CustomUserDetailsService.java) 按 **account** 加载用户；
2. 校验密码后写入 `SecurityContext`；
3. 签发 JWT，返回 `JwtResponse`：

| 字段 | 说明 |
| --- | --- |
| `accessToken` | JWT 字符串 |
| `tokenType` | 固定 `Bearer` |
| `userId`、`account`、`username`、`email` | 用户基本信息 |
| `discount` | 折扣（0.95 / 1.0 等） |
| `role` | `USER` / `ADMIN` |

### 4.2 JWT 机制

- 签名算法：HMAC-SHA，密钥来自 `jwt.secret`；
- `subject` 为账号 `account`，自定义 Claim `userId`；
- 有效期 24 小时；
- 前端在请求头携带 `Authorization: Bearer <token>`；
- [`JwtAuthenticationFilter`](../springboot/src/main/java/com/example/bookstore/security/JwtAuthenticationFilter.java) 校验 Token 并加载用户，将 `ROLE_USER` / `ROLE_ADMIN` 权限写入 `SecurityContext`；Token 过期时直接返回：

```json
{ "message": "登录已过期，请重新登录", "status": 401 }
```

### 4.3 Spring Security 配置

[`SecurityConfig`](../springboot/src/main/java/com/example/bookstore/security/SecurityConfig.java) 当前配置：

- 关闭 CSRF；
- 会话策略 `STATELESS`；
- **按路径 / HTTP 方法分级授权**（在 `permitAll()` 之前声明）：
  - `/api/admin/**`、`/api/coupons/admin/**` → `ROLE_ADMIN`
  - 图书 / 分类 / 标签的 POST / PUT / DELETE → `ROLE_ADMIN`
  - 其余 `/api/**` → `permitAll()`
- 其余请求需要认证；
- 跨域由独立的 [`CorsConfig`](../springboot/src/main/java/com/example/bookstore/config/CorsConfig.java) `CorsFilter` 处理：允许任意来源、任意请求头、GET/POST/PUT/DELETE/OPTIONS，允许携带凭证。

用户级接口仍由 Controller 手工鉴权，主要存在两种写法：

| 写法 | 使用位置 | 行为 |
| --- | --- | --- |
| `getUserIdFromRequest()` | 购物车、订单、地址、收藏、评论、笔记、消息、积分、签到、优惠券、余额等 | 解析 Bearer Token 查出用户 ID；为空返回 `401` |
| `isAdmin()` / `forbiddenIfNotAdmin()` | `AdminController` | 查询数据库校验 `role == ADMIN`，否则返回 `403`（Security 路径规则之外的第二道校验） |

### 4.4 当前鉴权矩阵（按模块）

| 模块 | 读接口 | 写接口 |
| --- | --- | --- |
| 图书 | 公开 | 管理员（Security 规则 + Controller） |
| 分类 | 公开 | 管理员（Security 规则） |
| 标签 | 公开 | 管理员（Security 规则） |
| 购物车、订单、地址、收藏、消息、积分、签到、余额 | 需登录 | 需登录且校验资源归属 |
| 评论、笔记 | 图书维度公开 | 需登录且校验作者本人 |
| 优惠券 | `/available` 公开，其余需登录 | 领取 / 试算需登录；`/admin/*` 需管理员 |
| 管理后台 `/api/admin/*` | 需管理员 | 需管理员 |

> 图书 / 分类 / 标签的写接口与优惠券管理接口已在 `SecurityConfig` 中统一要求 `ROLE_ADMIN`。

### 4.5 角色与折扣

- 角色枚举：`USER`、`ADMIN`；
- 折扣存储在 `users.discount`，下单时后端按 `书籍价格 × 用户折扣` 计算成交单价；
- 前端 `localStorage.discount` 仅用于展示；用户折扣变更后需要重新登录刷新该值。

## 5. 数据模型

### 5.1 数据表清单（20 张）

| 表名 | 实体 | 说明 | 关键字段 |
| --- | --- | --- | --- |
| `users` | `User` | 用户 | `account`、`username` 唯一；`password` BCrypt；`role`；`discount` |
| `categories` | `Category` | 图书分类 | `name` 唯一 |
| `books` | `Book` | 图书 | `isbn` 唯一；`price`、`stock`、`avg_rating`、`review_count`、`sales_count`、`image_url`；`category` 关联 |
| `cart_items` | `CartItem` | 购物车项 | `user`、`book`、`quantity` |
| `orders` | `Order` | 订单 | `user`、`total_price`、`status`、`shipping_address`、`phone` |
| `order_items` | `OrderItem` | 订单明细 | `order`、`book`、`quantity`、成交单价 `price` |
| `addresses` | `Address` | 收货地址 | `user_id`、收件人、省市区、详址、`is_default` |
| `banners` | `Banner` | 首页轮播 | `title`、`book_id`、`image_url`、`sort_order`、`status` |
| `quotes` | `Quote` | 名言 | `content`、`author_name`、可选 `book_id` |
| `reviews` | `Review` | 书评 | `user_id + book_id` 唯一；`rating` 1–5；`content` |
| `favorites` | `Favorite` | 收藏 | `user_id + book_id` 唯一 |
| `notes` | `Note` | 读书笔记 | `user_id`、`book_id`、`title`、`content`、`is_public`、`like_count` |
| `messages` | `Message` | 系统消息 | `user_id`、`title`、`content`、`type`（默认 SYSTEM）、`is_read` |
| `tags` | `Tag` | 标签 | `name` 唯一 |
| `book_tags` | `BookTag` | 图书-标签关联 | `book_id + tag_id` 唯一 |
| `coupons` | `Coupon` | 优惠券模板 | `type`（FIXED/PERCENT/MONEY_OFF）、`value`、`min_amount`、`total_num`、`used_num`、有效期 |
| `after_sales` | `AfterSale` | 售后工单 | `order_id`、`user_id`、`type`(REFUND/RETURN/EXCHANGE)、`reason`、`description`、`status`(PENDING/APPROVED/REJECTED/COMPLETED)、`admin_remark`、`refund_amount`、`handled_at` |
| `user_coupons` | `UserCoupon` | 用户领取的券 | `user_id`、`coupon_id`、`status`（UNUSED/USED）、`used_at` |
| `points_logs` | `PointsLog` | 积分流水 | `user_id`、`amount`、`type`（EARN/SPEND）、`description` |
| `check_ins` | `CheckIn` | 签到记录 | `user_id + check_in_date` 唯一；`consecutive_days` |
| `user_balance` | `UserBalance` | 用户余额 | `user_id` 唯一；`balance` |

### 5.2 关系图

```text
categories 1 ──── N books
users      1 ──── N orders 1 ──── N order_items N ──── 1 books
users      1 ──── N cart_items N ──── 1 books
users      1 ──── N addresses
users      N ──── N books        （favorites / reviews / notes 关联表）
users      N ──── N coupons      （user_coupons）
books      N ──── N tags         （book_tags）
users      1 ──── N points_logs / check_ins
users      1 ──── 1 user_balance
```

### 5.3 约定

- 主键均为 `GenerationType.IDENTITY` 自增；
- `created_at` / `updated_at` 通过实体的 `@PrePersist` / `@PreUpdate` 自动填充；
- 部分关联使用 JPA `@ManyToOne`（如 `orders → users`、`order_items → books`、`books → categories`），部分表仅保存数值型 `user_id` / `book_id`，不加外键约束；
- 金额统一使用 `BigDecimal`，数据库精度 `10,2`；评分 `3,1`；
- 无数据库迁移工具（如 Flyway/Liquibase），结构变更依赖 `ddl-auto=update`；
- 图书封面为本地静态资源，路径约定为 `/covers/{isbn}.jpg`，文件存放在 `vue/public/covers/`，抓取脚本见 `scripts/fetch-book-covers.mjs`。

## 6. API 接口清单

所有接口前缀为 `http://localhost:8080`。鉴权列含义：

- **公开**：无需 Token；
- **登录**：需要有效 Bearer Token（多数由 Controller 手工校验）；
- **管理员**：需要 `role=ADMIN`；
- **⚠️ 未校验**：当前代码未做权限判断。

### 6.1 认证 `/api/auth`

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册；仅当服务端配置了管理员密钥时可带 `adminSecret` | 公开 |
| POST | `/api/auth/login` | 登录，返回 JWT | 公开 |
| GET | `/api/auth/user` | 当前用户资料 | 登录 |
| PUT | `/api/auth/user` | 更新昵称 / 邮箱 / 手机 | 登录 |
| POST | `/api/auth/change-password` | 修改密码 | 登录 |

### 6.2 图书 `/api/books`

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| GET | `/api/books?categoryId=&keyword=&page=0&size=8` | 列表 / 分类 / 搜索 + 数据库分页（size 上限 100） | 公开 |
| GET | `/api/books/{id}` | 图书详情 | 公开 |
| POST | `/api/books` | 新增图书 | 管理员 |
| PUT | `/api/books/{id}` | 更新图书 | 管理员 |
| DELETE | `/api/books/{id}` | 删除图书 | 管理员 |

> 搜索字段为书名 / 作者 / ISBN（`Containing` 模糊匹配）。分页由 Spring Data `Pageable` 在数据库完成，列表查询使用 `@EntityGraph` 预取分类，避免 N+1。

### 6.3 分类 `/api/categories`

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| GET | `/api/categories` | 全部分类 | 公开 |
| GET | `/api/categories/{id}` | 分类详情 | 公开 |
| POST | `/api/categories` | 新增分类 | 管理员 |
| PUT | `/api/categories/{id}` | 更新分类 | 管理员 |
| DELETE | `/api/categories/{id}` | 删除分类 | 管理员 |

### 6.4 购物车 `/api/cart`

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/cart/add?bookId={id}&quantity={n}` | 加入购物车（重复加入累加） | 登录 |
| GET | `/api/cart` | 我的购物车 | 登录 |
| PUT | `/api/cart/{cartItemId}` | 修改数量，Body `{ "quantity": n }` | 登录 |
| DELETE | `/api/cart/{cartItemId}` | 移除一项 | 登录 |
| DELETE | `/api/cart/clear` | 清空购物车 | 登录 |

> 加入购物车与修改数量都会校验 `quantity` 为大于 0 的整数，并检查库存上限。
>
> 购物车项响应包含 `imageUrl`（图书封面），以及作者、单价、库存等展示字段，供购物袋与结算页使用。

### 6.5 订单 `/api/orders`

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/orders` | 直接创建订单（支持 `paymentMethod=balance` 扣余额），Body 含 `addressId`、`items`、`paymentMethod`、可选 `userCouponId` | 登录 |
| POST | `/api/orders/pending` | 创建待支付订单；有 `items` 时按明细创建，否则用购物车；可选 `userCouponId` | 登录 |
| GET | `/api/orders` | 我的订单列表（含 `couponDiscount`） | 登录 |
| GET | `/api/orders/{orderId}` | 订单详情（校验归属） | 登录 |
| PUT | `/api/orders/{orderId}/status` | 修改状态，Body `{ "status": "PAID" }`；仅允许白名单流转；取消时退回库存与优惠券 | 登录（校验归属 + 流转） |
| DELETE | `/api/orders/{orderId}` | 删除订单（仅限 `PENDING` / `CANCELLED`，校验归属） | 登录 |

> `POST /api/orders` 仅当 `paymentMethod="balance"` 且余额充足时直接生成 `PAID` 订单；其他支付方式一律先落为 `PENDING`。`POST /api/orders/pending` 创建待支付订单时会立即扣减库存。
>
> **优惠券**：传入 `userCouponId` 时，后端校验归属、状态与门槛（`minAmount` 按折后金额判断），计算抵扣并核销为 `USED`，订单写入 `couponDiscount` / `userCouponId`；订单取消时自动退回为 `UNUSED`。金额不足门槛返回 400「未达到最低消费金额」。
>
> **站内信**：下单成功自动发「订单已创建」，支付成功发「支付成功」，取消发「订单已取消」，后台发货 / 完成同样自动通知。
>
> **订单明细封面**：订单明细（`OrderItemDTO`）返回 `imageUrl`，订单列表、订单详情与支付页据此展示图书封面。

## 7. 核心业务流程

### 7.1 注册 / 登录

```text
注册：前端 → POST /api/auth/register → 唯一性校验 → BCrypt 加密
     → 默认 USER(0.95)；仅当服务端配置了 BOOKSTORE_ADMIN_SECRET
       且 adminSecret 匹配时才创建 ADMIN(1.0)
     → 返回 JWT + 用户信息 → 前端跳转登录页

登录：前端 → POST /api/auth/login → AuthenticationManager
     → CustomUserDetailsService 按 account 加载
     → 校验密码 → 签发 JWT → 前端写入 localStorage → 进入首页
```

- 登录页使用 **account**（账号），不是 username；
- 普通登录页 [`Login.vue`](../vue/src/views/Login.vue) **拒绝管理员账号登录**，提示「管理员请使用管理员后台登录」；
- 管理员登录页 [`AdminLogin.vue`](../vue/src/views/AdminLogin.vue) 登录成功后会额外校验 `role === ADMIN`，否则提示「该账号不是管理员账号」；
- 注册页未渲染 `adminSecret` 输入框；管理员也可直接在数据库中把用户 `role` 改为 `ADMIN`。

### 7.2 图书浏览

`GET /api/books` 根据参数选择数据源：

1. 有 `categoryId` → 按分类查询；
2. 有 `keyword` → 按书名 / 作者 / ISBN 模糊查询；
3. 否则 → 全量查询；
4. 通过 Spring Data `Pageable` 在数据库分页，返回统一的 `PageResult` 结构。

### 7.3 购物车

- 加入购物车时校验用户、图书与库存，并要求数量为大于 0 的整数；同一本书已存在则累加数量，并再次校验库存；
- 数量修改同样校验正数与库存，移除、清空均校验购物车项归属；
- 购物车 DTO 返回图书名、作者、单价、库存与封面 `imageUrl` 等展示字段。

### 7.4 结算与支付（当前主流程）

```text
购物车 /cart
  └─ 勾选商品 → /checkout?ids=1,2
        └─ 选择 / 新增地址；计算：
             原价合计 = Σ(单价 × 数量)
             会员价合计 = Σ(单价 × 0.95 × 数量)     ← 前端硬编码 95 折
             运费 = 会员价合计 ≥ 99 ? 0 : 10
             应付 = 会员价合计 + 运费
        └─ 不创建订单，携带 ids / addressId / 价格等 query 跳转 /payment
              └─ 选择支付宝或微信 → /scan-payment
                    └─ POST /api/orders/pending
                          items = [{ bookId, quantity, price }]
                          后端重新按 书籍价格 × 用户折扣 计算成交价并扣减库存
                          订单状态 = PENDING，返回 orderId
                    └─ 展示静态二维码，点击「完成支付」
                          └─ PUT /api/orders/{orderId}/status  { "status": "PAID" }
                          └─ 仅删除本次结算的购物车项（立即购买不触碰购物车）
                    └─ 跳转 /orders
```

「立即购买」路径 [`BuyNow.vue`](../vue/src/views/BuyNow.vue) 类似，只是携带 `bookId + quantity` 而非购物车 ID；扫码页会用 `bookId` 直接组装订单明细。

**关键事实：**

- 订单在第 4 步（扫码页）才真正创建，此时库存已被扣减；
- 支付是模拟的，没有支付回调或第三方验签；
- 后端订单金额**不包含运费**（`orders.total_price` 仅为商品成交合计）；
- 支付成功后只移除本次结算的购物车项，「立即购买」不会清空购物车；
- 订单列表的「去支付」现在进入支付/扫码页，不再直接改状态。

### 7.5 订单状态机

```text
PENDING ──模拟支付──▶ PAID ──管理员发货──▶ SHIPPED ──用户/管理员确认──▶ COMPLETED
PENDING ──用户或管理员取消──▶ CANCELLED（恢复库存）
PAID / SHIPPED ──管理员取消──▶ CANCELLED（恢复库存；已支付订单回退销量）
```

- 管理员发货仅允许 `PAID`；完成仅允许 `SHIPPED`；
- 用户端 `PUT /api/orders/{orderId}/status` 仅允许 `PENDING→PAID/CANCELLED`、`SHIPPED→COMPLETED`，其他流转返回 400；
- 用户取消 `PENDING` 订单会恢复库存并回退销量（如已支付）；
- 删除订单仅允许 `PENDING` / `CANCELLED`，删除待付款订单会恢复库存；
- 支付仍为模拟，`PENDING→PAID` 由客户端触发，尚无支付回调验签；
- 没有「超时未支付自动取消」任务。

### 7.6 价格与优惠计算

| 场景 | 计算方式 |
| --- | --- |
| 注册默认折扣 | `USER` 0.95，`ADMIN` 1.0 |
| 后端下单 | 成交单价 = `book.price × user.discount`；后端忽略前端传来的 `totalPrice` |
| 结算页展示 | 前端从 `localStorage.discount` 读取用户折扣（登录接口下发），与后端一致 |
| 运费 | 仅前端计算：会员价合计 ≥ 99 免运费，否则 10 元；不写入订单 |
| 优惠券 | 结算页选择后实时试算；下单时传 `userCouponId`，后端核销并写入 `orders.coupon_discount`，取消订单自动退回 |

### 7.7 签到与积分

签到流程：

1. 校验今日是否已签到；
2. 若昨天有签到记录，连续天数 +1，否则重置为 1；
3. 发放基础积分：

```java
int points = 10;
if (consecutiveDays >= 7) points = 15;
else if (consecutiveDays >= 3) points = 12;
```

4. 连续天数等于 7 / 15 / 30 时，额外发放 50 / 150 / 500 积分，并发站内信；
5. 连续签到满 7 天后可抽奖：`POST /api/checkin/lottery` 从积分奖池（10–200 分）随机取一个值，入账并写入 `check_ins.lottery_drawn`，当天只能抽一次；接口返回 `{ points, name, consecutiveDays }`，前端转盘以服务端结果为准；
6. 积分以流水形式记录（`type=EARN`），当前积分 = 所有 EARN 之和 − 所有 SPEND 之和。

积分目前只在签到、抽奖时获得；下单不返积分；`spendPoints` 没有对外接口。

### 7.8 优惠券

- 券类型：`FIXED`（固定减免）、`PERCENT`（百分比减免）、`MONEY_OFF`（固定减免，与 `FIXED` 等价）；
- 可领取条件：状态 `ACTIVE`、未过期、`used_num < total_num`、同一用户没有同券的 `UNUSED` 记录；
- 领取时立即 `used_num + 1`；
- 试算规则：必须为 `UNUSED`，达到 `min_amount` 后按类型计算减免额；
- **下单核销**：`OrderService.createOrderEntity` 调用 `CouponService.useCoupon` 校验券归属与状态、按折后金额判断门槛、计算抵扣并把券置为 `USED`；订单记录 `coupon_discount` 与 `user_coupon_id`；
- **取消退回**：用户取消或后台取消订单时调用 `restoreCoupon` 把券恢复为 `UNUSED`；
- **结算页**：地址、商品、配送、优惠券、费用明细联动，选择的券实时调用 `/api/coupons/calculate` 试算。

### 7.9 评论、笔记、收藏、标签

- **评论**：每人每书一条；评分 1–5；创建 / 修改 / 删除后重新计算 `books.avg_rating` 与 `review_count`；只有作者本人能修改 / 删除；
- **笔记**：按图书展示；支持公开 / 私有；只有作者本人能修改 / 删除；点赞直接 `like_count + 1`，没有去重或取消；
- **收藏**：用户与图书唯一关联，支持切换收藏状态；
- **标签**：全局标签库 + 图书关联表，标签名唯一；可创建标签并挂到图书上。

### 7.10 后台管理

- **Dashboard**：统计 `USER` / `ADMIN` 数量、订单各状态数量、总营收（排除 `CANCELLED`）、图书总数、库存 < 10 的图书数；
- **订单**：发货、完成、取消（恢复库存）；
- **图书**：CRUD + 批量调价；百分比模式为「在原价基础上加 adjustment%」，固定模式为「原价 + adjustment」，结果必须大于 0；
- **用户**：查看列表与角色切换；有订单的用户不允许删除。

## 9. 二次开发指南

### 9.1 新增后端接口

1. 在 `entity` 定义表映射（如需要）；
2. 在 `repository` 定义查询方法；
3. 在 `service` 编写业务逻辑，写操作加 `@Transactional`；
4. 在 `controller` 暴露 REST 接口，按现有模式校验登录态 / 管理员；
5. 若新增字段，重启后由 `ddl-auto=update` 自动补列（生产建议改用迁移脚本）。

现有手工鉴权模式示例：

```java
private Long getUserIdFromRequest(HttpServletRequest request) {
    String authorization = request.getHeader("Authorization");
    if (authorization != null && authorization.startsWith("Bearer ")) {
        try {
            String account = jwtUtil.extractUsername(authorization.substring(7));
            User user = userRepository.findByAccount(account).orElse(null);
            if (user != null) return user.getId();
        } catch (Exception ignored) {}
    }
    return null;
}

// Controller 中
Long userId = getUserIdFromRequest(request);
if (userId == null) return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
```

> 新接口建议优先考虑在 `SecurityConfig` 中按路径 / 角色声明权限，而不是继续复制手工解析逻辑。

### 9.2 新增前端页面

1. 在 `views` 新建 `.vue` 页面；
2. 在 `api/index.js` 增加对应 API 模块；
3. 在 `router/index.js` 注册路由，并决定是否加入 `requiresAuth`；
4. 若涉及导航，可在 `Navbar.vue` 或用户下拉菜单添加入口。

### 9.3 新增数据表

1. 新建实体并标注 `@Entity`、`@Table`、`@Id`；
2. 新建 `JpaRepository`；
3. 需要种子数据时在 `DataInitializer` 中补充（注意幂等）；
4. `ddl-auto=update` 会在启动时建表；生产环境建议引入 Flyway。

### 9.4 开发约定

- 金额使用 `BigDecimal`，禁止用 `double` 参与金额计算；
- 业务异常抛 `CustomException(message, status)`，由全局处理器统一返回；
- 用户提示信息使用中文；
- 写操作保持事务边界在 Service 层；
- 前端请求统一走 `api/index.js`，不要在页面里直接创建 Axios 实例；
- 前端页面使用 `<script setup>` 组合式 API。

### 7.10 订单超时自动取消

- 实现：`task/OrderTimeoutTask.java` + `OrderService.closeExpiredOrders(timeoutMinutes)`，主类已开启 `@EnableScheduling`；
- 规则：`PENDING` 状态且 `created_at` 早于「当前时间 − 超时分钟数」的订单会被置为 `CANCELLED`，同时回滚库存、退回优惠券、发送站内信；
- 配置（`application.yml`）：

```yaml
bookstore:
  order-timeout:
    minutes: 30          # 未支付超时时间
    initial-delay: 30000 # 启动后首次扫描延迟（毫秒）
    task-interval: 60000 # 扫描间隔（毫秒）
```

- 排查：把 `logging.level.com.example.bookstore=DEBUG` 打开可看到每轮扫描的阈值与命中数量；
- ⚠️ **时区注意**：JDBC URL 使用 `serverTimezone=UTC`，应用写入的 `datetime` 字面量比 JVM 本地时间小 8 小时。应用内部读写一致、页面显示正常，但**直接用 SQL（如 `NOW()`）比对或手工造数据时会出现 8 小时偏差**，测试时请按同样偏移写入。
