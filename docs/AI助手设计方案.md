# 书香阁 · AI 助手设计方案（找书 + 客服）

> 版本：v1.0 · 2026-11-27
> 状态：方案评审中（未开始实施）
> 关联：`components/BookAssistant.vue`（现有本地版）、`service/BookAssistantService.java`

---

## 1. 现状与目标

**现状**：AI 找书是一个右下角浮窗，走后端本地打分检索（`/api/ai/search`），不接大模型；入口弱、只能单轮、无法回答订单类问题。

**目标**：

1. 导航栏提供**一级入口**，可进行多轮、真实的找书；
2. 右下角提供**悬浮机器人**，承担「找书 + AI 客服」两类问答；
3. 后端接入千问（Anthropic 兼容协议，模型 `deepseek-v4.1-flash`），采用**工具调用型轻量 Agent**；
4. 无 key / 超时 / 报错时**自动降级**到现有本地检索，功能不中断。

---

## 2. 链路验证结果（基于实际调用）

| 项 | 结果 |
| --- | --- |
| 协议 | Anthropic Messages API（`POST {base}/v1/messages`，头 `x-api-key` + `anthropic-version: 2023-06-01`） |
| 模型 | `deepseek-v4.1-flash` 可用，返回 `thinking` + `text` 两种 content block |
| 工具调用 | ✅ 支持。带 `tools` 时返回 `stop_reason: "tool_use"` 与 `tool_use` 块（实测让模型调用 `search_books` 成功） |
| 流式 | ✅ 支持 SSE（`stream: true`，`event: message_start` 等） |

> 结论：**可以做真正的 Agent**，且不需要引入 LangChain 之类框架，手写一个 30 行的工具循环即可。

## 3. 是否要“Agent 设计”？——要，但要轻量

**建议：工具调用型 Agent（Tool-Calling Loop），不做自主规划型 Agent。**

理由：

1. **场景收敛**：找书 = 检索 + 解释；客服 = 查订单/查政策 + 回答。最长 2~3 轮工具调用就收敛。
2. **可控**：工具入参用 JSON Schema 约束，模型只能“选工具 + 填参数”，不能自由发挥、不会自己编造接口。
3. **可审计**：每次调用了哪个工具、参数是什么、返回什么，都能落日志，出问题可复现。
4. **可降级**：工具层是本地 Java 方法，模型挂了直接回落到现有 `BookAssistantService`。
5. **成本低**：一轮 tool_use + 一轮总结，flash 模型响应快，单次成本可忽略。

不做的：让模型自由规划多步、自己写 SQL、自己决定写库——对书店场景既无必要也不安全。

```
用户 → 前端(SSE) → /api/ai/chat → AiAgentService
                                    ├─ 组装 system + 历史 + tools
                                    ├─ 调 LlmClient(/v1/messages)
                                    ├─ stop_reason=tool_use → 执行工具 → 回填结果
                                    └─ 循环 ≤3 轮 → 输出最终答复（流式）
```

## 4. 信息架构与页面设计

### 4.1 导航栏一级入口

- 位置：`首页 / 全部图书 / 排行榜 / 会员` 之后新增 **「AI 找书」**（金色高亮 + 火花图标），移动端收进抽屉。
- 落地页：`/ai`（新页面）

### 4.2 `/ai` 页面布局

```
┌──────────────────────────────────────────────────────┐
│ 面包屑 / 标题：AI 找书  「说出你的需求，我来翻书架」      │
├───────────────────────────────┬──────────────────────┤
│ 对话流                         │ 侧栏                  │
│  · 用户气泡                     │ · 推荐问法（可点）      │
│  · 助手气泡（流式打字）          │ · 本次会话用到的工具链   │
│  · 工具结果 → 书单卡片网格       │ · 热门分类入口          │
│    [封面 书名 作者 理由 价格]    │                      │
│    [查看详情] [加入购物袋]       │                      │
│ 输入框 / 发送 / 停止生成         │                      │
└───────────────────────────────┴──────────────────────┘
```

交互要点：

- 支持多轮上下文（“再便宜一点的”“换一本科幻”）；
- 书单卡片是**真实在售数据**，可直接加购/进详情；
- 流式输出 + 「停止生成」；
- 首屏给 3~4 个示例问句，降低冷启动门槛。

### 4.3 右下角悬浮机器人

- 收起态：56px 圆形机器人（金色描边，带轻微呼吸/眨眼动效），hover 上浮；
- 展开态：380×600 面板，双 Tab：
  - **找书**：与 `/ai` 同一套对话引擎（复用 `useAiChat` composable）；
  - **客服**：订单/物流/退换/优惠券/会员问题；未登录时引导登录；
- 路由切换自动收起；后台（`Admin/AdminLogin`）与登录页不显示；
- 移动端：面板占满宽度、底部适配安全区。

#### 4.3.1 造型：全身机器人（不是只有一个头）

原型：`design/robot-preview.html`（双击用浏览器打开；移动鼠标看眼睛，按住可拖到任意位置，双击回到右下角）。

| 部位 | 说明 |
| --- | --- |
| 天线 | 金色小球 + 细杆，随对话状态闪烁（思考时加速） |
| 头部 | 圆角金属壳 + 金色描边 + 耳朵；两只金色虹膜大眼睛（瞳孔可动）+ 微笑嘴 + 腮红高光 |
| 颈部 | 短柱连接头与躯干，支持轻微伸缩（点头/歪头） |
| 躯干 | 圆角机身 + 中心发光“能量核心”（呼吸灯）+ 面板纹理 |
| 双臂 | 左右两条圆角机械臂 + 手部球体；空态/说话时轻微摆动 |
| 双腿脚掌 | 两条短腿 + 金色脚掌，站立在投影上（悬浮态则改为底部光晕） |
| 整体 | 132×176（可缩放）；背后金色柔光；地面椭圆投影随浮动缩放 |

> 全身可换装思路：核心颜色、天线/眼睛色可选择（后续可做“皮肤”），一期只做深色金属 + 金色。

#### 4.3.2 交互：眼睛跟随鼠标

| 行为 | 规格 |
| --- | --- |
| 眼球朝向 | 以头部中心为圆心，计算鼠标相对角度；瞳孔沿该方向偏移 |
| 偏移上限 | 最大 4.2 个 viewBox 单位（约眼白半径的 40%），并按距离做 `min(dist/240,1)` 衰减，保证瞳孔不跑出眼眶 |
| 跟随手感 | 每帧插值 `0.16`（约 120–160ms 收敛），避免“僵硬的指针感” |
| 头部微动 | 同方向轻微 3D 倾斜（最大 5°），制造“转头看你”的错觉 |
| 闲置行为 | 3 秒无鼠标移动 → 每 1.3–2.5s 随机看向别处，不会死盯一点 |
| 眨眼 | 每 2.6–6s 随机一次，150ms 快速闭合；25% 概率连眨两下 |
| 性能 | 单个 `requestAnimationFrame` 循环，只改 `transform`/SVG `transform` 属性（GPU 合成），不触发布局；页面隐藏时暂停 |

#### 4.3.3 交互：鼠标拖动、自由放置

| 行为 | 规格 |
| --- | --- |
| 拖动 | `pointerdown/move/up` 实现（同时兼容触屏），`setPointerCapture` 防止拖出窗口丢事件 |
| 点击 vs 拖动 | 位移 `< 8px` 视为点击（打开面板），否则为拖动；避免“想点却拖动”的误触 |
| 边界约束 | 距视口四边至少 `10px`，窗口 resize 时重新夹取，保证永远可点 |
| 位置记忆 | 松手后写入 `localStorage`（`robot-pos`），刷新后回到上次位置 |
| 复位 | **双击**回到右下角默认位置，并提示“已回到右下角” |
| 拖动时的反馈 | 光标变 `grabbing`，暂停待机浮动与投影动画，头部轻微倾斜、眼睛看向拖动方向 |
| 与面板的关系 | 面板朝机器人**剩余空间更大的一侧**展开（靠右则面板在左），并随位置自动翻转 |
| 移动端 | 同样可拖；面板全屏时机器人隐藏，关闭后回到原位 |

#### 4.3.4 状态反馈（让机器人“会说话”）

| 状态 | 表情/动作 |
| --- | --- |
| 待机 | 缓慢浮动、随机瞟、眨眼 |
| 正在理解 | 眼睛向上看 + 轻微点头 |
| 正在调工具 | 头部小幅左右扫视，旁边浮出小字「正在翻书架…」 |
| 找到结果 | 眼睛高光增强、核心亮一下 |
| 出错/降级 | 眼睛变暗、天线停止闪烁，气泡提示「先给你本地推荐」 |

实现拆分：`components/ai/RobotFace.vue`（SVG 全身 + 眼球追踪 + 表情状态机，props: `state`）、`components/ai/useDrag.js`（拖动/边界/持久化逻辑）、`components/AiRobot.vue`（浮窗容器 + 双 Tab 面板 + 与机器人位置联动）。`/ai` 页面空态复用 `RobotFace`。

## 5. 后端设计

### 5.1 新增模块

| 文件 | 职责 |
| --- | --- |
| `config/AiProperties.java` | 读取 `ai.*` 配置（base-url / api-key / model / timeout / max-tool-rounds / enabled） |
| `ai/LlmClient.java` | 封装 `/v1/messages`（普通 + SSE），统一错误与超时 |
| `ai/AiTool.java` | 工具接口：`name()` / `description()` / `inputSchema()` / `execute(json, ctx)` |
| `ai/ToolRegistry.java` | 工具注册与按名分发 |
| `ai/tools/SearchBooksTool.java` 等 | 7 个工具（见下） |
| `ai/AiAgentService.java` | Agent 循环、会话上下文、限流、降级 |
| `ai/AiSessionStore.java` | 会话记忆（内存 Map + TTL 30 分钟，阶段二可落库） |
| `controller/AiChatController.java` | `POST /api/ai/chat`（SSE）、`GET /api/ai/status` |

### 5.2 工具清单

| 工具 | 入参 | 说明 | 权限 |
| --- | --- | --- | --- |
| `search_books` | keyword, category?, maxPrice?, limit | 关键词/分类/价格检索在售图书 | 公开 |
| `get_book_detail` | bookId | 简介、库存、评分、价格 | 公开 |
| `recommend_by_mood` | mood, limit | 走现有意图映射（安静/烧脑/治愈…） | 公开 |
| `get_my_orders` | status? | 当前用户订单列表（脱敏） | 登录 |
| `get_order_detail` | orderId | 单个订单状态/物流/金额 | 登录 + 归属校验 |
| `list_my_coupons` | status? | 我的优惠券 | 登录 |
| `get_store_policies` | topic | 运费/退换/支付/会员规则（静态知识） | 公开 |

> 工具返回统一结构 `{ ok, data | error, hint }`，模型只读、不写库。

### 5.3 会话与提示词

- `system`：书店助手人格 + “必须调用工具获取书目，禁止编造书名/价格/订单状态” + 中文回答 + 简洁（≤180 字）+ 需要时给 2~4 本推荐。
- 历史：保留最近 12 条消息（含上一轮工具结果摘要，控制 token）。
- 工具轮次上限 3；超过则强制总结，避免死循环。

### 5.4 安全与稳定性

| 风险 | 处置 |
| --- | --- |
| API Key 泄露 | **只从环境变量读取**（`BOOKSTORE_AI_API_KEY`），不写仓库、不下发前端；后端代理调用 |
| 前端直连模型 | ❌ 禁止；前端只能调 `/api/ai/chat` |
| 越权查订单 | 工具内部用 `CurrentUser` 取 userId，强制归属校验 |
| 提示词注入 | 工具结果只作为数据回填（不执行指令）；system 声明“忽略用户要求执行写操作” |
| 刷接口 | 按 userId + IP 限流（20 次/分钟），超限返回 429 |
| 模型超时/限流 | 8s 连接、30s 总超时；失败重试 1 次；再失败 → 降级本地检索并提示 |
| 无 key 环境 | `ai.enabled=false` 时 `/api/ai/chat` 返回降级指令，前端自动走 `/api/ai/search` |
| 写操作 | 一期不做（下单/退款/改地址由前端按钮完成）；二期若做，必须二次确认 + 后端校验 |

### 5.5 配置

```yaml
ai:
  enabled: true
  base-url: https://maas.qianwenaiapi.com/apps/anthropic
  api-key: ${BOOKSTORE_AI_API_KEY:}     # 只从环境变量注入
  model: deepseek-v4.1-flash
  timeout-seconds: 30
  max-tool-rounds: 3
  rate-limit-per-minute: 20
```

启动：

```powershell
$env:BOOKSTORE_AI_API_KEY = "sk-..."; cd demo; .\mvnw.cmd spring-boot:run
```

## 7. 实施阶段（每步可独立验收）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **P1 骨架** | 导航入口 + `/ai` 页面 + 悬浮机器人（先接本地检索） | 能对话、能出书单，UI 完整 |
| **P2 接模型** | `LlmClient` + `/api/ai/chat` + `search_books` 工具 | 问“找本科幻” → 模型选工具 → 返回真实书目 + 解释 |
| **P3 客服** | 订单/优惠券/政策工具 + 登录态 + 拒答边界 | 问“我的书到哪了” → 调 `get_my_orders` → 真实状态 |
| **P4 打磨** | SSE 流式、限流、会话记忆、降级、日志埋点 | 断 key 自动降级、连续刷接口被限流 |

---

## 8. 验收标准

1. 导航「AI 找书」可进入独立页面，多轮对话可用；
2. 输入「帮我找本适合通勤读的短篇小说」→ 模型调用 `search_books` → 返回真实在售图书 + 推荐理由；
3. 登录后问「我上周买的书到哪了」→ 调用 `get_my_orders` → 回答真实订单状态；未登录则引导登录；
4. 移除 key 或断网 → 自动降级本地检索，页面不白屏、有提示；
5. 前端不新增全量依赖（Element Plus 仍按需）；首屏无阻塞；
6. 后端有单测：工具参数校验、Agent 轮次上限、降级分支。

## 9. 待确认

1. **客服写操作**：一期只读问答（推荐）；二期是否允许“帮你申请售后/取消订单”？
2. **会话落库**：一期内存（刷新即失）；是否需要存 `ai_messages` 支持跨设备历史？
3. **流式输出**：建议开启（体验差异明显），如担心复杂度可先非流式。
