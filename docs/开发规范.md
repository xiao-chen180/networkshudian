## 1. 仓库与目录规范

### 1.1 仓库根目录只放「长期资产」

允许存在于仓库根目录的内容：

```text
demo/
├── .github/workflows/     # CI
├── .editorconfig
├── .gitignore
├── README.md
├── docs/                  # 项目文档
├── springboot/            # 后端模块
├── vue/                   # 前端工程
├── pom.xml                # Maven 聚合
├── mvnw / mvnw.cmd
└── scripts/               # 确需保留的一次性脚本（默认不建）
```

禁止：

- 调试脚本（`fix*.js`、`test-*.html`、`query` 等）提交到根目录；确实需要保留的放 `scripts/` 并在文件头写明用途；
- 重复资源（同一张图片不要同时在 `picture/` 和 `vue/public/` 存两份）；
- 本地构建产物（`target/`、`dist/`、`node_modules/`）进入版本库；
- IDE 配置（`.idea/`、`.vscode/`）进入版本库。

### 1.2 命名

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 目录 / 包 | 全小写，单词用 `.` / `-` 分隔 | `com.example.bookstore.service` |
| Java 类 | 大驼峰 | `OrderService`、`OrderStatus` |
| Java 方法 / 字段 | 小驼峰 | `createOrder`、`totalPrice` |
| 常量 | 全大写下划线 | `MAX_PAGE_SIZE` |
| Vue 组件文件 | 大驼峰 | `BookCard.vue` |
| JS 变量 / 函数 | 小驼峰 | `loadBooks` |
| API 路径 | 复数名词、kebab-case | `/api/order-items` |

### 1.3 分支与提交

- 主分支 `main` 始终保持可构建、可运行；
- 功能分支 `feature/<简述>`、修复分支 `fix/<简述>`；
- 提交信息使用 Conventional Commits：
  `feat: 支持优惠券结算` / `fix: 修复购物车结算参数` / `docs: 更新开发文档` / `refactor:` / `test:` / `chore:`。

## 2. 后端规范

### 2.1 分层职责

| 层 | 只做 | 不做 |
| --- | --- | --- |
| `controller` | 接收参数、校验、调用 Service、组装响应 | 写业务逻辑；直接注入 Repository；手工解析 Token |
| `service` | 业务规则、事务边界、编排多个 Repository | 处理 HTTP 状态码细节（抛业务异常即可） |
| `repository` | 数据访问与查询 | 业务判断 |
| `entity` | 表映射与生命周期回调 | 作为接口出入参 |
| `dto` | 接口契约（请求 / 响应） | 承载 JPA 注解 |

**硬性规则：**

1. Controller 不得直接调用 Repository（现有 `RankingController`、`RecommendController`、`BannerController`、`QuoteController` 需改造）。
2. 同一资源的写接口只保留一套；管理端写操作统一放 `/api/admin/**`，公开接口只读。
3. 业务逻辑不得在 Controller 中复制；价格计算、订单创建等抽到 Service。

### 2.2 鉴权

- 统一通过 Spring Security 获取当前用户：

```java
@GetMapping
public ResponseEntity<List<AddressDTO>> list(@AuthenticationPrincipal UserDetails user) {
    return ResponseEntity.ok(addressService.listByAccount(user.getUsername()));
}
```

- 管理接口通过路径规则或方法级注解授权：

```java
@EnableMethodSecurity
// ...
@PreAuthorize("hasRole('ADMIN')")
@PostMapping("/api/admin/books")
public ResponseEntity<BookDTO> create(@Valid @RequestBody BookDTO dto) { ... }
```

- 禁止在每个 Controller 复制 `getUserIdFromRequest()`、`isAdmin()`。
- 用户资源必须校验归属（订单、地址、收藏、笔记、评论、消息、优惠券）。
- 未登录返回 `401`，无权限返回 `403`，二者不要混用。

### 2.3 DTO 与参数校验

- 所有请求体使用 DTO，禁止直接用 Entity 接收（现有 `AddressController`、`CategoryController` 需改造）。
- 请求 DTO 必须加校验注解，Controller 参数加 `@Valid`：

```java
public record CreateAddressRequest(
        @NotBlank String name,
        @NotBlank @Pattern(regexp = "^1\\d{10}$") String phone,
        @NotBlank String province,
        @NotBlank String city,
        @NotBlank String detail
) {}
```

- 响应同样使用 DTO，不直接返回 Entity；金额字段使用 `BigDecimal`。
- 禁止用 `Map<String, Object>` 作为请求体（订单、评论、笔记、后台接口需逐步替换）。

### 2.4 枚举与常量

- 订单状态、用户角色、优惠券类型、支付方式、消息类型必须使用枚举：

```java
public enum OrderStatus { PENDING, PAID, SHIPPED, COMPLETED, CANCELLED }
```

- 数据库中可存枚举 `name()`，DTO 中输出字符串；禁止散落字符串字面量。

### 2.5 事务

- 所有多表写操作在 Service 层加 `@Transactional`；
- 只读查询可加 `@Transactional(readOnly = true)`；
- 事务内不要做远程调用、文件 IO、长时间计算；
- 并发敏感写操作（库存、余额）使用原子更新 / 乐观锁 / 悲观锁，禁止简单「读-判断-写」。

### 2.6 异常与日志

- 业务异常统一抛 `CustomException`，由 `GlobalExceptionHandler` 转换为统一响应；
- 禁止 `printStackTrace()`、`System.out.println()`，统一用 SLF4J；
- 500 响应不得包含异常原文、SQL、堆栈、文件路径；
- 建议错误响应带业务错误码：

```json
{ "code": "ORDER_STOCK_NOT_ENOUGH", "message": "库存不足", "status": 400 }
```

### 2.7 查询与分页

- 禁止 `findAll()` 后在内存分页、排序；统一使用 `Pageable` / `Page`；
- 列表查询避免 N+1：使用 `JOIN FETCH`、`@EntityGraph` 或 DTO 投影；
- 统计接口使用聚合 SQL，不把全表读进内存；
- 单次请求分页大小上限 100。

### 2.8 数据库与迁移

- 使用 Flyway（或 Liquibase）管理表结构，`spring.jpa.hibernate.ddl-auto=validate`；
- 禁止开发环境 `update` 直接带到生产；
- 表、字段命名使用 `snake_case`；外键与唯一约束显式声明；
- 金额字段 `DECIMAL(10,2)`，时间字段统一 `datetime`。

### 2.9 配置

- 按环境拆分 `application-dev.yml` / `application-prod.yml`；
- 数据库密码、JWT 密钥、管理员密钥一律通过环境变量注入，仓库中不出现明文；
- `spring.jpa.open-in-view` 设为 `false`；
- 生产关闭 `show-sql`。

## 3. 前端规范

### 3.1 目录职责

```text
vue/src/
├── api/            # request.js（Axios 实例/拦截器）+ auth.js/book.js/order.js/admin.js
├── stores/         # Pinia：auth.js、cart.js、ui.js
├── composables/    # useAuth、useCart、usePagination、useCountdown
├── components/     # common/、book/、order/
├── views/          # 页面，仅负责组合
├── router/
├── styles/         # 变量、全局样式
└── utils/          # 纯函数工具
```

### 3.2 组件

- 单文件建议不超过 500 行；超过则按区块拆子组件或抽 composable；
- 页面（views）只做布局与编排，业务逻辑放 composable / store；
- 组件命名语义化，避免 `Header` 与 `Navbar` 两个同名概念混用；
- 删除无引用组件与工具，禁止长期保留「备用代码」。

### 3.3 状态管理

- 登录态、用户信息、购物车数量统一放 Pinia：

```js
// stores/auth.js
export const useAuthStore = defineStore('auth', {
  state: () => ({ token: '', user: null }),
  getters: { isLoggedIn: s => !!s.token, isAdmin: s => s.user?.role === 'ADMIN' },
  actions: {
    async login(payload) { /* ... */ },
    logout() { /* ... */ }
  }
})
```

- 页面中禁止直接散写 `localStorage.getItem('token')`；
- localStorage 仅作为持久化插件使用；路由守卫读取 store，不读裸 key。

### 3.4 API 调用

- 所有请求通过 `api/` 模块，禁止在页面创建 Axios 实例；
- `request.js` 统一处理 Token 注入与 401/403；
- 接口返回结构变化时同步更新 API 模块与页面，禁止页面自行拼 URL。

### 3.5 样式

- 颜色、间距、圆角、阴影全部使用 CSS 变量（`styles/variables.css`）；
- 深色模式通过 `:root.dark` 覆盖变量，禁止页面写死 `#fff` / `#333`；
- 图片必须优先使用后端返回的 `imageUrl`，缺失时使用本地占位图，禁止依赖外链随机图。

### 3.6 交互状态

每个数据页面至少处理三种状态：

1. **加载中**：loading 占位（骨架屏或 spinner）；
2. **空数据**：明确的空状态文案；
3. **请求失败**：错误提示 + 重试入口。

禁止 `catch (e) {}` 静默吞错。

### 3.7 路由与权限

- 前端权限只用于体验，**最终权限以服务端为准**；
- 应用启动时校验会话（`GET /api/auth/user`），失效则清理登录态；
- 统一处理 401（跳登录）与 403（提示无权限）；
- 提供 `NotFound.vue`，未知路径显示 404 而不是重定向首页（可按需选择）。

### 3.8 工具链

- ESLint + Prettier + EditorConfig；
- Element Plus 按需引入，避免主包过大；
- 推荐逐步引入 TypeScript（至少对 API 模块与 store 使用 JSDoc / TS）。

## 4. 接口契约规范

### 4.1 URL 与状态码

- 统一前缀 `/api`，资源名用复数：`/api/books`、`/api/orders`；
- 管理端统一 `/api/admin/**`；
- 状态码：`200` 查询/更新、`201` 创建、`204` 删除、`400` 参数/业务校验、`401` 未登录、`403` 无权限、`404` 不存在、`409` 冲突、`500` 服务端错误。

### 4.2 分页结构

```json
{
  "content": [],
  "totalElements": 0,
  "totalPages": 0,
  "number": 0,
  "size": 10
}
```

### 4.3 时间与金额

- 时间统一 ISO-8601（`2026-11-25T10:00:00`），前端负责展示格式化；
- 金额一律字符串或数值两位小数，禁止浮点误差；后端使用 `BigDecimal`。

### 4.4 接口文档

- 使用 springdoc-openapi 生成 Swagger UI（`/swagger-ui/index.html`）；
- DTO 字段加 `@Schema(description = "...")`；
- 接口变更必须同步更新本文档与 `docs/开发文档.md` 的 API 清单。

## 5. Git 与协作规范

- 一个提交只做一件事；不把格式化、重构、功能混在一起；
- 提交前必须本地通过：后端编译、前端构建；
- 不提交密钥、`.env.local`、IDE 配置、构建产物；
- PR 描述包含：变更内容、影响范围、验证方式、截图（涉及 UI）；
- 合并前至少 1 人 Review，CI 必须通过。

## 6. 测试与 CI 规范

### 6.1 最低测试要求

- 新增业务逻辑必须补单元测试；
- 核心链路（注册登录、购物车、下单、支付、订单状态、优惠券）必须有集成测试；
- 鉴权必须测试：未登录 401、非管理员 403、越权访问他人资源 403。

### 6.2 CI 流程

`.github/workflows/ci.yml` 已配置：

1. 后端：JDK 17 + `mvn package`；
2. 前端：Node 20 + `npm ci` + `npm run build`。

后续补充：`mvn test`、`npm run lint`、构建产物上传。

## 7. 代码评审清单

**后端**

- [ ] Controller 是否只做参数与响应编排？
- [ ] 是否使用 DTO，且请求体有 `@Valid` 校验？
- [ ] 是否校验了资源归属与角色？
- [ ] 写操作是否有事务？并发敏感操作是否原子？
- [ ] 是否新增了字符串魔法值？
- [ ] 是否有全表加载、N+1、内存分页？
- [ ] 异常是否泄露内部信息？
- [ ] 配置/密钥是否外置？

**前端**

- [ ] 页面是否超过 500 行？能否拆分？
- [ ] 是否直连 localStorage / Axios？
- [ ] 是否处理 loading / empty / error 三态？
- [ ] 是否使用 CSS 变量、兼容深色模式？
- [ ] 是否引入外链图片/写死地址？
- [ ] 路由与权限是否以服务端为准？
